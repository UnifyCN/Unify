## Problem

The RAG knowledge base has 20 documents, all from November 2025 — 4 months stale. There is no ingestion pipeline in the codebase. Documents were loaded manually via an external process (scrape websites → convert to markdown → upload to S3 → manually embed). This is tedious, error-prone, and nobody does it — resulting in outdated immigration information served to users.

## Vision

### 10x Check
An always-current immigration intelligence system that monitors 50+ trusted government pages, detects policy changes within hours, auto-generates "what changed" summaries, and proactively notifies users whose profiles match affected policies. Every response shows "last verified: 2 hours ago" with deep links to exact source pages.

### Platonic Ideal
A living mirror of canada.ca/IRCC — always within hours of the source. Every chunk carries provenance: source URL, fetch timestamp, content version hash. The AI knows what it doesn't know — stale data gets flagged. Users feel the assistant reads the IRCC website every morning. Crawl failures are visible, not silent.

## Architecture

```
                         TRUSTED URL ALLOWLIST
                         ┌──────────────────┐
                         │ ircc.canada.ca   │
                         │ canada.ca/en/... │
                         │ www2.gov.bc.ca   │
                         └────────┬─────────┘
                                  │
                    ┌─────────────▼──────────────┐
                    │   ingest-documents          │
                    │   (Supabase Edge Function)  │
                    │                             │
                    │  1. Fetch URL               │
                    │  2. HTML → clean text        │
                    │  3. Compute content_hash    │
                    │  4. Skip if hash unchanged  │
                    │  5. Chunk text              │
                    │  6. Quality score chunks    │
                    │  7. OpenAI embed each chunk │
                    │  8. Upsert (write-then-swap)│
                    │  9. Log to crawl_logs       │
                    └──────┬──────────────────────┘
                           │
              ┌────────────▼─────────────┐
              │     Supabase Postgres     │
              │  knowledge_documents      │
              │    + updated_at           │
              │    + content_hash         │
              │    + source_url           │
              │  knowledge_chunks         │
              │    + updated_at           │
              │  crawl_logs (NEW)         │
              │  match_chunks() + recency │
              └────────────┬─────────────┘
                           │
              ┌────────────▼─────────────┐
              │     rag-query             │
              │  + source_url passthrough │
              │  + last_verified timestamp│
              └──────────────────────────┘

  TRIGGER: pg_cron (daily) → one URL per invocation
```

## Key Decisions

- **One URL per invocation** to stay within Supabase edge function 150s timeout
- **Write-then-swap** for atomic updates — old chunks stay until new ones are fully written
- **Content hashing** (SHA-256) for change detection — skip unchanged pages
- **Hardcoded URL allowlist** — ensures only trusted gov sources are crawled
- **Recency-boosted retrieval** — `final_score = similarity * 0.85 + recency_factor * 0.15`

## Accepted Scope
- Full automated crawler for trusted gov URLs with content hashing
- Schema updates: updated_at, content_hash, source_url columns
- "Last verified" timestamps in AI responses
- Deep-link source URLs in citations
- Crawl health monitoring (crawl_logs table)
- Recency-boosted retrieval in match_chunks()
- Content quality scoring for chunks
- Change detection logging (foundation for future push notifications)
